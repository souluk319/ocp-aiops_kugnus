Fact-based Version Book

Kugnus OCP AIOps 버전별 작업 기록

이 문서는 Ver.0.1.0부터 Ver.0.1.5까지의 산출물과 커밋 흐름을 기준으로 작성한 단일 HTML 기록이다. 목적은 지금까지 어떤 작업이 실제로 이루어졌는지, 어떤 기능이 구현되었는지, 전체 제품 기준으로 어디까지 왔는지를 꾸밈없이 정리하는 것이다.

개요

현재 repo는 OpenShift 기본 콘솔을 대체하는 별도 제품이 아니라, OpenShift 콘솔 안에서 동작하는 Cywell AI / KOMSCO AIOps 관제탑과 챗봇을 만드는 작업 공간이다. 로컬 WSL 개발환경에서 Gateway와 console plugin을 띄우고, 회사 OCP는 read-only 관측 대상으로 연결한다.

현재 확인된 최종 작업선은 feat/v.0.1.5다. 0.1.4에서 PBS 계열 사용자 업로드/RAG 기능을 선별 이식했고, 0.1.5에서 RCA ToolPlan, runbook evidence, Lightspeed payload boundary, UI verifier 증거 저장까지 시연 하드닝을 진행했다. 단, 이는 로컬 WSL 개발 콘솔 기반 시연 준비이며 회사 OCP 신규 설치 완료를 뜻하지 않는다.

목표

버전별 목표는 다음처럼 변했다.

버전 주 목표 작업 성격
Ver.0.1.0 Kugnus 전용 카탈로그/OLM 방향, 이름 분리, 안전선, 기본 UI/아이콘 기준 고정 방향 고정, 카탈로그 준비, 기존 회사 리소스와 충돌 방지
Ver.0.1.1 Tool Plan, Evidence/RCA Context, RAG/Runbook skeleton, OS Adapter, OLM readiness, 평가 세트 고도화 AIOps 기능 계약과 검증 기반 구축
Ver.0.1.2 실제 회사 OCP read-only 신호를 로컬 관제탑에 연결하고 Stage 1-6을 검증 자동화까지 완료 로컬 관제탑 제품 흐름 구현, 자동 검증, 운영 시나리오 작성

Ver.0.1.4 PBS 프로젝트의 사용자 업로드/RAG 파이프라인을 분석하고, PDF/MD 업로드와 pgvector citation smoke를 연결 사용자 문서 기반 RAG 도입, 업로드 패널/문서 근거 흐름 보강
Ver.0.1.5 시연 직전 RCA/Runbook ToolPlan, Lightspeed boundary, fallback 표현, UI verifier evidence를 하드닝 시연 멘트 안전선과 검증 증거를 고정한 demo readiness 단계

기능범위

현재 포함된 범위

  • 로컬 WSL Gateway와 로컬 OpenShift console bridge 기반 개발환경
  • 회사 OCP API에 대한 read-only 관측과 console proxy/UserToken 기반 UI 확인
  • Kugnus 전용 package/catalog/namespace/ConsolePlugin 이름 분리 기준
  • Cywell AI 관제탑 UI, 챗봇 shell, 상태 카드, 이상 징후, RCA 근거, read-only 조치 후보
  • Tool Plan JSON, RCA Context JSON, Evidence/Missing Evidence 계약
  • PDF/MD 사용자 업로드를 pgvector RAG evidence로 연결하는 local smoke 경로
  • OLM/Operator readiness manifest와 local-only 검증
  • UI verifier, Gateway pytest, frontend build, offline scenario evaluator, demo live verifier를 묶은 검증 루프

현재 포함되지 않은 범위

  • 별도 승인 없는 회사 OCP runtime 설치, Subscription 생성, AIOpsInstallation 생성
  • 기존 공용 komsco-ai-console-plugin 또는 lightspeed-console-plugin 교체
  • 실제 mutation 실행: oc apply/delete/patch/scale/exec
  • production RAG 품질 보장, 모델 학습 파이프라인, 장기 운영 피드백 학습
  • Lightspeed stream 최종 응답 성공 보장. 현재는 stream 실패나 장기 대기 시 Gateway fallback/stop 복구를 명시한다.

진행도

진행도는 세 기준으로 나눠서 봐야 한다. 0.1.2 로컬/read-only 계획 범위는 Stage 1-6이 완료되어 100%다. 0.1.5 로컬 시연 준비 범위는 smoke, scenario, Evidence/RCA, live cycle, screen readiness, UI verifier, frontend build, backend tests가 모두 PASS라 100%로 본다. 반면 운영 제품 전체 기준은 회사 OCP 설치/운영 rollout, production RAG 품질, 승인 기반 action execution 운영 검증이 남아 있어 약 82%로 판단한다.

Ver.0.1.0

방향 고정 카탈로그 준비 설치 별도 승인

개요

0.1.0은 프로젝트 방향을 고정한 버전이다. 기준 문서는 OpenShift_Lightspeed_커스터마이징_구축_수행_방안.pdf이며, 기존 Lightspeed와 공용 KOMSCO plugin을 보존한 상태에서 Kugnus 전용 Gateway, Dynamic Console Plugin, Operator/OLM 모델을 얹는 방향으로 정리했다.

목표

  • Kugnus 전용 package, catalog, namespace, ConsolePlugin 이름을 기존 공용 리소스와 분리한다.
  • Software Catalog/OperatorHub에 카드가 보이고, 별도 승인 시 설치 가능한 패키지 구조를 준비한다.
  • 실제 설치와 AIOpsInstallation 생성은 승인 전까지 하지 않는다.

기능범위

이름 분리 komsco-aiops-kugnus, komsco-aiops-catalog-kugnus, komsco-ai-kugnus, komsco-ai-console-plugin-kugnus
UI/브랜드 K_icon.png, komsco_logo.svg/png, Cywell AI / KOMSCO AI 계열 표시 기준
안전선 기존 공용 ConsolePlugin/Lightspeed 미수정, token/kubeconfig/.env commit 금지, 설치성 task 금지
실행 문서 WSL 개발, task be:dev, task fe:dev, task kugnus:package, task kugnus:publish, task kugnus:status 기준 정리

구현된 것

  • 0.1.0 README에 PDF 요구사항 추적표, 금지 명령, Kugnus 전용 이름 기준, 완료 기준이 정리되었다.
  • 문서상 2026-06-24 publish 결과로 komsco-aiops-catalog-kugnus CatalogSource와 komsco-aiops-kugnus PackageManifest가 기록되어 있다.
  • 문서상 Gateway/Console plugin ImageStreamTag, catalog READY, PackageManifest currentCSV가 기록되어 있다.
  • 기존 공용 komsco-ai-console-plugin과 lightspeed-console-plugin은 유지 대상으로 명시됐다.

아직 하지 않은 것

  • Subscription, CSV, AIOpsInstallation 생성은 하지 않은 상태로 기록되어 있다.
  • Kugnus ConsolePlugin은 install 단계에서 생성되는 항목으로 남았다.
  • 0.1.0의 핵심은 제품 방향과 카탈로그 준비이지, 운영 runtime 완성은 아니다.

Ver.0.1.1

기능 계약 평가 세트 offline 중심

개요

0.1.1은 UI만 다듬는 단계가 아니라, AIOps 판단력의 기반이 되는 계약을 만든 단계다. 최종 PDF 요구사항을 기준으로 Tool Plan JSON, RCA Context JSON, Evidence, RAG/Runbook, OS Adapter, OLM readiness, 평가 체계를 나눠서 정리했다.

목표

  • 질문을 바로 답변하지 않고 Tool Plan과 Evidence 수집 흐름으로 연결한다.
  • 증거가 없는 답변은 단정하지 않고 missing evidence로 남긴다.
  • RAG/Runbook이 실제로 설정되지 않았으면 not_configured로 표시한다.
  • OLM/Operator readiness가 local manifest와 status condition에서 재현되게 한다.
  • 한국어 운영 시나리오를 pass/fail로 평가하는 offline evaluator를 만든다.

기능범위

Stage 작업 내용 상태

2 Evidence footer와 bearer/kubeconfig redaction 강화 PASS
3 RAG/Runbook search skeleton과 not_configured 계약 PASS, production RAG backend는 미구현
4 OS Adapter status와 capability 계약 PASS

6 Action lifecycle UX와 read-only 기본 안전선 PASS
7 OLM/Operator readiness, CRD status conditions/components PASS, local package/manifest 검증
8 한국어 AIOps scenario evaluator 5종 PASS, offline contract evaluation

구현된 것

  • evals/aiops-scenarios/에 Pod restart, CrashLoopBackOff, ImagePullBackOff, ClusterOperator degraded, CronJob activity 시나리오가 추가되었다.
  • scripts/evaluate-aiops-scenarios.py가 Tool Plan, RCA Context, Safety Contract, forbidden hallucination을 검증한다.
  • task kugnus:evaluate 경로가 추가되었다.

  • Stage 7은 local package/contract 검증이며 공식 회사 OCP에 CatalogSource, Subscription, AIOpsInstallation을 생성하지 않았다.

Ver.0.1.4
