작업 방식

  • 큰 변경 전에는 목표, 완료 조건, 검증 방법, 하지 않을 것을 먼저 잠근다.
  • 실패 원인은 실제 단위로 이름 붙인다. 예: manifest mismatch, stale port, auth expired.
  • UI 작업 후에는 task kugnus:ui:verify 또는 해당 route/DOM 검증을 붙인다.
  • 새 버전으로 넘어갈 때는 현재 버전 커밋/푸시 후 새 브랜치를 먼저 만든다.
