아침에는 새 판단을 시작하지 말고, 먼저 살아 있는지 확인하고, PASS 기준을 보고, 마지막에 브라우저에서 사람 눈으로 답변 품질을 본다.

자동 검증 기준 PASS로컬 개발 콘솔회사 OCP 설치 아님

1. 첫 명령

VS Code 또는 Ubuntu 터미널에서 WSL Ubuntu 프롬프트를 연다. PowerShell이 아니라 kugnus@KugnusCywell 형태의 Ubuntu 터미널이다.

cd /home/kugnus/cywell/ocp-aiops_kugnus
task kugnus:dev:doctor
정상FAIL=0. WARN은 이미 포트가 떠 있는 경우면 정상 범위.
중단oc login, Docker daemon, Gateway healthz 실패가 있으면 먼저 복구.

2. 자동 검증 순서

아래 순서로 한 줄씩 실행한다. 이미 전날 밤 모두 PASS였지만, 아침에는 환경이 재부팅됐을 수 있으므로 다시 확인한다.

task kugnus:runtime:smoke
task kugnus:scenario:verify
task kugnus:evidence-rca:verify
task kugnus:demo:live-verify
task kugnus:demo:screen-readiness
runtime smokerag=collected backend=pgvector configured=True results=3가 핵심.
scenarioscenarioCount=10, passed=10, failed=0.
Evidence/RCApass면 공식 장면 계약은 유지됨.
live/screenpass면 시연 사이클과 화면 준비도 계약 유지.

3. 브라우저 수동 확인

자동 검증이 PASS면 브라우저를 연다.

http://localhost:9000/dashboards

챗봇을 열고 이 질문을 넣는다.

어제 새벽에 default namespace Pod가 왜 재시작됐어?
  • 상단에 노드 수, Health, Operator 상태, 실행 모드가 보이는지 확인한다.
  • 답변이 Evidence/RCA/RAG/runbook 흐름처럼 보이는지 확인한다.
  • 답변이 너무 일반론이면 발표용으로는 미흡하다고 본다.
  • 실행 가능 모드와 실험 무제한 모드가 구분되어 보이는지 확인한다.

4. 실패 시 바로 볼 것

Unauthorizedoc login 토큰 만료. 웹콘솔에서 새 토큰으로 로그인.
Docker daemon 실패Docker Desktop 실행, WSL integration Ubuntu 확인.
RAG missingtask kugnus:rag:dev:up 후 backend를 task kugnus:dev:be:execute:rag로 재시작.
Action Executor 18083 실패curl http://127.0.0.1:18083/healthz 확인. 죽어 있으면 backend execute:rag 재시작.
9000 already in usecurl -I http://127.0.0.1:9000/dashboards가 200이면 정상적으로 이미 떠 있는 것.
