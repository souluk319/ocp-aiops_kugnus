베스트 한 사이클

공식 목표: 사용자가 "어제 새벽에 default namespace Pod가 왜 재시작됐어?"라고 묻고, AI Gateway가 event/grep/metric/snapshot evidence 계획과 RCA Context 구조를 만들며, 로컬 콘솔에서는 해당 공식 질문을 Cywell AI Troubleshooting 모드에 올리는 것을 증명한다.
  1. 대시보드에서 현재 클러스터 컨텍스트와 위험 신호를 확인한다.
  2. 공식 질문을 chat에 넣어 Pod restart RCA로 분류한다.
  3. Tool Plan이 event_tool, grep_tool, metric_tool, snapshot_tool을 선택한다.
  4. RCA Context digest와 collected/missing evidence가 답변 footer에 남는다.
  5. 최종 답변 계약은 RCA, 즉시 조치, 재발 방지책, 참고 증적 관점을 포함한다.
  6. action candidate는 제안만 하며 실행하지 않는다.
  7. CrashLoopBackOff verifier는 화면/stream 연결 smoke test로 계속 유지한다.
주의: 현재 브라우저 증거는 질문 staging과 Gateway fallback 답변 렌더링 proof다. 안정적인 Lightspeed 최종 RCA 완료나 실제 회사 OCP의 default namespace 과거 증적 완전 수집으로 말하지 않는다. 최신 코드에서는 공식 namespace restart collector가 Event, Pod snapshot, previous log pattern probe를 read-only로 시도하고, 없거나 권한이 부족한 증거는 collected/partial/skipped 상태로 드러낸다.

금지선

  • 회사 OCP에 설치, 배포, catalog 등록, OLM install을 실행하지 않는다.
  • oc apply/delete/patch/scale/exec류 mutation 명령을 실행하지 않는다.
  • 기존 komsco-ai-console-plugin, lightspeed-console-plugin을 교체하지 않는다.
  • CrashLoop 로그 원문은 민감정보 가능성이 있으므로 표시하지 않고 availability/필요 여부만 다룬다.
  • 근거 없는 추정을 RCA 확정처럼 표현하지 않는다.
