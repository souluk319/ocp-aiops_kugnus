Ver.0.1.0 catalog publish and repeatable install practice guide

Cywell AI 카탈로그 등록은 완료, 런타임 설치는 아직 하지 않은 상태

이 문서는 Kugnus 전용 AIOps 패키지를 OpenShift OperatorHub/Software Catalog에 노출한 자동화 과정과, 같은 과정을 수동으로 반복하는 방법을 함께 남긴다. 기본 제품 경험은 챗봇이고, 대시보드는 챗봇이 실제 AIOps 판단을 하도록 현재 연결 상태와 증적 상태를 보여주는 관제 화면이다.

제품 관점

1. 기본은 챗봇 OpenShift 운영자가 자연어로 묻고, Gateway가 사용자 토큰과 안전 정책을 붙여 Lightspeed/RCA 흐름으로 연결한다.
2. 대시보드는 챗봇의 관제탑 Cluster health, Lightspeed 연결, Tool Plan, Evidence, OS Adapter, 감사 기록을 보여줘서 챗봇 답변이 어떤 근거 위에 서 있는지 드러낸다.
3. 설치는 OLM으로 반복 가능해야 함 CatalogSource와 PackageManifest가 먼저 보이고, 승인 후 Subscription과 AIOpsInstallation이 runtime을 만든다.

자동화로 수행한 publish 과정

현재 회사 환경에서는 Docker Desktop이 외부 registry route DNS를 직접 resolve하지 못할 수 있으므로, 선호 경로는 OpenShift 내부 binary build다. 

cd /mnt/c/Users/soulu/cywell/ocp-aiops_kugnus
task kugnus:package
KOMSCO_AIOPS_IMAGE_BUILD_STRATEGY=openshift task kugnus:publish
task kugnus:status

참고: 기존 komsco-ai-gateway:0.1.2 또는 komsco-ai-console-plugin:0.1.2 ImageStreamTag가 이미 있으면 스크립트는 기본적으로 재빌드하지 않고 재사용한다. 소스 변경분까지 새 이미지로 반영하려면 KOMSCO_AIOPS_FORCE_IMAGE_BUILD=true를 함께 지정한다.

자동화 단계 실제 의미 생성/변경 대상
ensure namespace Kugnus 전용 작업장을 만든다. Namespace/komsco-ai-kugnus
OpenShift binary build 소스를 cluster builder에 업로드해서 내부 registry에 이미지를 만든다. BuildConfig, ImageStreamTag
package OLM CSV, CRD, CatalogSource, catalog ConfigMap manifest를 생성한다. olm/generated
apply catalog OperatorHub/Software Catalog에 Kugnus 카드가 보이도록 등록한다. CatalogSource, PackageManifest
wait package OLM이 catalog를 읽고 package를 노출할 때까지 기다린다. komsco-aiops-kugnus

같은 과정을 수동으로 하면 이렇게 된다

아래는 자동화가 내부에서 한 일을 사람이 순서대로 이해하기 위한 절차다. 실습할 때는 자동화 명령을 우선 사용하고, 수동 절차는 문제 원인 파악용으로 본다.

1. 로그인과 context 확인

oc whoami
oc whoami --show-server
oc project

2. Kugnus namespace 준비

oc get ns komsco-ai-kugnus || oc create ns komsco-ai-kugnus

3. ImageStream과 BuildConfig 준비

재실습 시 이미 존재하는 리소스 때문에 멈추지 않도록 oc get ... || oc create ... 형태로 만든다. 

oc get imagestream komsco-ai-gateway -n komsco-ai-kugnus \
  || oc create imagestream komsco-ai-gateway -n komsco-ai-kugnus

oc get imagestream komsco-ai-console-plugin -n komsco-ai-kugnus \
  || oc create imagestream komsco-ai-console-plugin -n komsco-ai-kugnus

oc get buildconfig komsco-ai-gateway -n komsco-ai-kugnus \
  || oc new-build --binary --strategy=docker \
  --name=komsco-ai-gateway \
  --to=komsco-ai-gateway:0.1.2 \
  -n komsco-ai-kugnus

oc get buildconfig komsco-ai-console-plugin -n komsco-ai-kugnus \
  || oc new-build --binary --strategy=docker \
  --name=komsco-ai-console-plugin \
  --to=komsco-ai-console-plugin:0.1.2 \
  -n komsco-ai-kugnus

4. 소스 업로드와 이미지 빌드

먼저 자동화와 같은 방식으로 작은 staging directory를 만든다.

rm -rf /tmp/komsco-aiops-kugnus-build
mkdir -p /tmp/komsco-aiops-kugnus-build/komsco-ai-gateway
mkdir -p /tmp/komsco-aiops-kugnus-build/komsco-ai-console-plugin

tar -C /mnt/c/Users/soulu/cywell/ocp-aiops_kugnus/komsco-ai-gateway \
  --exclude='./.venv' \
  --exclude='./__pycache__' \
  --exclude='./.pytest_cache' \
  --exclude='./.ruff_cache' \
  --exclude='*.pyc' \
  --exclude='*.log' \
  -cf - . | tar -C /tmp/komsco-aiops-kugnus-build/komsco-ai-gateway -xf -

tar -C /mnt/c/Users/soulu/cywell/ocp-aiops_kugnus/komsco-ai-console-plugin \
  --exclude='./node_modules' \
  --exclude='./dist' \
  --exclude='./integration-tests/screenshots' \
  --exclude='./integration-tests/videos' \
  --exclude='./.yarn/install-state.gz' \
  --exclude='*.log' \
  -cf - . | tar -C /tmp/komsco-aiops-kugnus-build/komsco-ai-console-plugin -xf -

그 다음 staging directory를 BuildConfig에 업로드한다.

oc start-build komsco-ai-gateway \
  -n komsco-ai-kugnus \
  --from-dir=/tmp/komsco-aiops-kugnus-build/komsco-ai-gateway \
  --follow --wait

oc start-build komsco-ai-console-plugin \
  -n komsco-ai-kugnus \
  --from-dir=/tmp/komsco-aiops-kugnus-build/komsco-ai-console-plugin \
  --follow --wait

주의: 실제 스크립트는 node_modules, dist, .venv 등을 제외한 staging directory를 만든 뒤 업로드한다. repo 전체를 그대로 올리면 매우 느려질 수 있다.

5. 이미지 pull 권한 부여

oc policy add-role-to-group system:image-puller system:serviceaccounts:komsco-ai-kugnus -n komsco-ai-kugnus

8. 선택 설치는 별도 승인 후

KOMSCO_AIOPS_APPROVE_INSTALL=komsco-ai-kugnus task kugnus:install

이 단계에서야 Subscription, CSV, AIOpsInstallation, ConsolePlugin/komsco-ai-console-plugin-kugnus, gateway/plugin deployment가 생성된다.

9. 승인된 Kugnus 전용 uninstall

KOMSCO_AIOPS_APPROVE_UNINSTALL=komsco-ai-kugnus task kugnus:uninstall

uninstall은 Kugnus 전용 리소스만 대상으로 한다. 다만 uninstall/install manifest가 Namespace/komsco-ai-kugnus나 runtime 리소스를 삭제할 수 있으므로, 실행 전 olm/generated와 스크립트가 지울 리소스를 반드시 확인한다. 기존 komsco-ai, komsco-ai-dev, komsco-ai-jk, lightspeed-console-plugin은 삭제 대상이 아니다.

로컬 개발 loop

카탈로그 등록 전 UI와 Gateway를 확인할 때는 아래 두 터미널만 유지한다. 첫 번째 터미널은 Gateway와 Lightspeed port-forward를 계속 실행하고, 두 번째 터미널은 로컬 OpenShift console bridge와 plugin webpack dev server를 실행한다. 

# Terminal A
AIOPS_GATEWAY_MODE=read-only task be:dev

# Terminal B, first run only
INSTALL_DEPS=true task fe:dev

# Terminal B, after dependencies exist
task fe:dev
  • Pass: Gateway가 http://127.0.0.1:18080에서 뜬다.
  • Pass: 로컬 콘솔이 http://localhost:9000에서 뜬다.
  • Pass: assistant proxy 경로가 komsco-ai-console-plugin-kugnus를 사용한다.
  • 주의: WSL에서 console container가 WSL Gateway에 붙어야 하면 Gateway를 0.0.0.0로 열고 WSL IP를 proxy endpoint로 써야 한다. host.docker.internal은 Windows 쪽 다른 서비스로 향할 수 있다.
  • Fail: 실험 무제한 또는 unrestricted mode가 회사 OCP 기본값으로 사용된다.

절대 하지 않을 것

  • task olm:deploy, task olm:release, task olm:install을 기본 경로로 실행하지 않는다.
  • task catalog:deploy, task catalog:release, task catalog:runtime:apply를 실행하지 않는다.
  • 기존 ConsolePlugin/komsco-ai-console-plugin을 덮어쓰지 않는다.
  • 기존 ConsolePlugin/lightspeed-console-plugin을 제거하지 않는다.
  • 기존 active console plugin 목록을 임의로 바꾸지 않는다.
  • .env, token, kubeconfig, password, private key를 commit하지 않는다.

Pass/Fail 확인

  • Pass: CatalogSource 상태가 READY다.
  • Pass: PackageManifest/komsco-aiops-kugnus가 보인다.
  • Pass: Subscription이 비어 있다. 기본 publish는 설치가 아니다.
  • Pass: 기존 komsco-ai-console-plugin backend namespace가 komsco-ai다.
  • Pass: active plugin 목록에 기존 값만 있고 Kugnus plugin은 아직 없다.
  • Fail: Kugnus 설치 전인데 ConsolePlugin/komsco-ai-console-plugin-kugnus가 생성돼 있다면 설치 경로가 실행된 것이다.

운영 UI 검토 기준

영역 해야 할 일 이유
Chatbot 전역 assistant launcher와 chat stream을 기본 경험으로 유지한다. 헤더와 상태/모드 메뉴는 한 줄에 통합하고, 별도 context strip row를 두지 않는다. AIOps 사용자는 대시보드를 보다가도 결국 질문과 조치 후보를 챗봇으로 받는다.
Cluster health node/operator/workload 상태를 요약한다. 운영자가 현재 장애 맥락을 빠르게 잡는다.
Lightspeed link OLS base URL, stream 상태, fallback 상태를 노출한다. 챗봇 답변이 Lightspeed와 연결됐는지 확인한다.
Tool Plan read-only 실행 계획과 금지된 mutation을 명확히 보여준다. Agentic 기능이 위험한 자동 실행으로 오해되지 않게 한다.
Evidence events/logs/metrics/runbook/audit의 수집 또는 누락 상태를 표시한다. 근거 없는 답변을 성공처럼 보이지 않게 한다.
OS Adapter OpenShift/Linux/Windows adapter의 가능 범위를 분리한다. PDF의 OS-aware AIOps 방향을 제품 화면에 연결한다.

5회 검토 루프 기록

Pass 1 Product UX: chatbot-first 부족, 상태 과장, 헤더/메뉴 분리로 인한 공간 낭비 지적. Cywell AI 통합 헤더, K 아이콘 토글, read-only UX, pending 상태 표시로 보완. fixed
Pass 2 AIOps architecture: Tool Plan/Evidence/Adapter가 실제보다 앞서 보인다는 지적. safety contract에 contract-only 상태를 명시. fixed
Pass 3 OLM/catalog safety: install/deploy 혼동과 protected plugin overwrite 위험 지적. Kugnus 전용 승인 env와 protected name guard 반영. fixed
Pass 4 Learner guide: staging directory, 수동 env, evidence, local dev loop 누락 지적. 자동/수동 경로와 pass/fail evidence 보강. fixed
Pass 5 Build/runtime consistency: Kugnus proxy name, logo asset, untracked files, legacy path 혼동 지적. Kugnus task와 docs를 현재 구현 기준으로 정리. fixed
