Ver.0.1.4 RAG 아키텍처 설계

0.1.4의 목표는 RAG를 “연결됨” 상태에서 “운영자가 믿고 근거로 볼 수 있는 구조”로 끌어올리는 것이다.

설계 단계pgvector 유지production 설치 아님

1. 목표

  • 수집 대상 문서, chunking, metadata, embedding, retrieval, evidence 연결을 명확히 설계한다.
  • 검색 결과가 없거나 부족한 경우를 숨기지 않고 missing evidence로 표시한다.
  • 위험한 실행 문서는 답변에서 바로 실행 명령으로 승격하지 않는다.
  • RAG 검색 결과가 Evidence/RCA 답변과 UI에 출처와 함께 연결되게 한다.

  1. OpenShift 운영 runbook
  2. KOMSCO/Cywell AIOps 자체 조치 절차
  3. 장애 유형별 RCA template
  4. 승인/실행 정책 문서
  5. 과거 시연/실습 시나리오 문서
  6. OpenShift 공식 문서 중 필요한 좁은 범위
  7. 회사 환경 특화 namespace/service/ConsolePlugin/Operator 설명
수집 금지: token, kubeconfig, .env, password, private key, 출처 없는 인터넷 복붙 문서.

4. 데이터 모델

documents

source_type, source_uri, title, version, owner, freshness, trust_level을 가진 원본 문서 테이블.

chunks

heading_path, content, summary, tags, os_scope, ocp_version_min/max, safety_class, embedding을 가진 검색 단위.

retrieval_events

query, scenario_id, top_k, selected_chunk_ids, missing_reason을 기록하는 감사/평가 테이블.

evidence_refs

답변에 실제로 인용된 chunk와 UI footer/source panel을 연결하는 참조 구조.
