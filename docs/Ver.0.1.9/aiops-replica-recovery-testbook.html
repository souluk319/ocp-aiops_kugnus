Ver.0.1.9 직접 검증용

AIOps Replica 부족 자동 복구 테스트북

이 문서는 배경지식 없이도 한 줄씩 따라가며 AIOps 챗봇의 핵심 흐름을 확인하기 위한 테스트북입니다. 목표는 이상 상태를 직접 만들고, 눈으로 보고, 챗봇에게 묻고, 답변 안의 승인/실행 버튼으로 복구하고, 다시 눈으로 복구 근거를 확인하는 것입니다.

오늘의 성공 기준

대상 komsco-ai-dev/aiops-two-pod-exec
정상 상태 Pod 3개 Running / Ready
일부러 만들 이상 replicas 1로 낮춰 Pod 1개만 보이게 함
AIOps 조치 답변 안 버튼으로 replicas 3 복구
1. 내가 만듦터미널에서 Deployment replicas를 1로 낮춘다.
2. 내가 봄콘솔과 터미널에서 Pod가 1개인지 확인한다.
3. 내가 물음챗봇에게 현재 Pod 수와 문제를 질문한다.
4. AI가 제안답변 안에 해결 방법과 승인/거절 버튼이 나온다.
5. 내가 승인승인 후 실행 버튼을 눌러 복구한다.
6. 내가 다시 봄Pod가 3개로 돌아왔는지 콘솔/터미널/챗봇으로 확인한다.
판정기준증거
Pass해결 전 Pod 1개, 해결 후 Pod 3개가 보인다.oc get deployment, oc get pods, 챗봇 마지막 답변
Fail승인/실행 버튼이 없거나, 실행 후 Pod가 3개가 아니다.버튼 화면, Gateway 상태, 터미널 오류
Stop대상 Deployment가 없거나, 권한이 없거나, 실행 가능 모드가 꺼져 있다.아래 멈춤 조건에 해당

절대 먼저 확인할 것

이 테스트는 실제 OpenShift Deployment의 replica 수를 바꿉니다. 운영 서비스에 하지 말고, 반드시 테스트 대상 aiops-two-pod-exec에만 진행하세요.

0

WSL 터미널에서 프로젝트 폴더로 이동

WSL 터미널에서 입력
cd /home/kugnus/cywell/ocp-aiops_kugnus
정상: 명령이 조용히 끝나고 프롬프트가 다시 뜹니다.
1

내가 어느 서버를 보고 있는지 확인

WSL 터미널에서 입력
oc whoami
oc whoami --show-server

이 명령은 변경을 만들지 않습니다. 지금 로그인한 사용자와 서버 주소만 보여줍니다.

멈춤: oc: command not found, You must be logged in, 원하지 않는 서버 주소가 나오면 여기서 멈추세요.
2

대상 Deployment가 진짜 있는지 확인

WSL 터미널에서 입력
oc -n komsco-ai-dev get deployment aiops-two-pod-exec
oc -n komsco-ai-dev get pods -l app=aiops-two-pod-exec
정상: 첫 줄에 aiops-two-pod-exec가 보이고, Pod 목록이 1개 이상 보입니다.
멈춤: NotFound가 나오면 이 테스트 대상이 아직 없습니다. 이 경우 scale 명령을 치지 마세요.
3

내 계정이 scale 조치를 할 수 있는지 확인

WSL 터미널에서 입력
oc auth can-i get deployments -n komsco-ai-dev
oc auth can-i update deployments/scale -n komsco-ai-dev
정상: 두 줄 모두 yes가 나오면 진행할 수 있습니다.
멈춤: 하나라도 no면 버튼을 눌러도 실행이 실패합니다. 권한부터 해결해야 합니다.
4

HPA가 이 Deployment를 자동 조정하지 않는지 확인

WSL 터미널에서 입력
oc -n komsco-ai-dev get hpa -o wide

HPA는 자동으로 replica 수를 바꾸는 장치입니다. 이 테스트에서는 사람이 만든 1개 상태가 잠깐 유지되어야 하므로, HPA가 같은 Deployment를 잡고 있으면 결과가 흔들립니다.

정상: No resources found이거나, HPA 대상에 aiops-two-pod-exec가 없습니다.
멈춤: HPA 대상이 aiops-two-pod-exec면 이 테스트를 그대로 진행하지 마세요.

작업대 준비

이미 로컬 콘솔과 Gateway가 떠 있으면 이 섹션은 확인만 하면 됩니다. 안 떠 있으면 아래 순서대로 켭니다.

1

상태만 먼저 진단

WSL 터미널에서 입력
task kugnus:dev:doctor

이 명령은 상태 확인용입니다. 포트와 Gateway, 콘솔 연결 상태를 봅니다.

정상: Gateway healthz, console bridge가 통과합니다.
2

작업대가 꺼져 있으면 복구

WSL 터미널에서 입력
task kugnus:demo:resume

이 명령의 내부 흐름은 아래와 같습니다.

task kugnus:demo:resume
  -> Taskfile.yml
    -> scripts/kugnus-demo-resume.sh
      -> Gateway 18080 확인 또는 시작
      -> Lightspeed 18443 port-forward 확인
      -> Action Executor 18083 port-forward 확인
      -> local console 9000 확인
정상: 마지막에 demo stack 또는 strict gate 관련 PASS가 보입니다.
멈춤: VPN, oc login, stale port 오류가 나오면 메시지를 그대로 보고 먼저 고쳐야 합니다.
3

브라우저에서 콘솔 열기

브라우저 주소창
http://localhost:9000/aiops-kugnus
정상: KOMSCO AI AGENT 또는 Cywell AI 화면이 보이고, 우측/상단에 실행 모드가 보입니다.
4

실행 가능 모드인지 확인

챗봇 상단 또는 실행 상태 영역에서 아래를 확인합니다.

  • 실행 가능 모드를 선택합니다.
  • Mutations on 또는 실행 가능 상태가 보여야 합니다.
  • Action Executor URL not configured 같은 blocker가 보이면 멈춥니다.
멈춤: 버튼이 비활성화되어 있고 tooltip에 실행 가능 또는 실험 무제한 모드 선택 필요, Gateway 실행 기능 미구성이 나오면 이 테스트는 아직 실행할 수 없습니다.

이상 상태 만들기

여기서부터는 서버에 실제 변경이 생깁니다. Deployment aiops-two-pod-exec의 replica 수를 1로 낮춰서 일부러 이상 상태를 만듭니다.

1

정상 기준을 먼저 기록

WSL 터미널에서 입력
oc -n komsco-ai-dev get deployment aiops-two-pod-exec
oc -n komsco-ai-dev get pods -l app=aiops-two-pod-exec

이 화면을 스크린샷으로 남기면 좋습니다. 나중에 복구 전후 비교에 씁니다.

2

replicas를 1로 낮추기

WSL 터미널에서 입력
oc -n komsco-ai-dev scale deployment/aiops-two-pod-exec --replicas=1
oc -n komsco-ai-dev rollout status deployment/aiops-two-pod-exec --timeout=120s
정상: deployment.apps/aiops-two-pod-exec scaled와 rollout 완료 메시지가 보입니다.
멈춤: 권한 오류, NotFound, timeout이 나오면 다음 단계로 가지 말고 오류를 기록하세요.

해결 전 이상 상태를 눈으로 확인

1

터미널에서 1개인지 확인

WSL 터미널에서 입력
oc -n komsco-ai-dev get deployment aiops-two-pod-exec
oc -n komsco-ai-dev get pods -l app=aiops-two-pod-exec

2

콘솔에서 1개인지 확인

브라우저에서 확인

  2. Workloads 또는 Deployments 화면으로 이동합니다.

해결 전 Pod 1개 화면을 눈으로 확인했다.

질문 1: 챗봇에게 현재 상태를 묻기

첫 질문은 조치가 아니라 확인입니다. AI가 실제 상태를 읽는지 확인합니다.

챗봇 입력창에 그대로 붙여넣기
komsco-ai-dev 네임스페이스의 aiops-two-pod-exec 파드 몇 개 떠 있어?

답변에서 봐야 할 것

  • komsco-ai-dev/aiops-two-pod-exec 대상이 나와야 합니다.
  • 현재 Pod 수가 1개라고 나와야 합니다.
  • 근거 또는 evidence footer가 붙어야 합니다.
  • lightspeed_stream 오류나 fallback만 보이면 Gateway/OLS 상태를 확인합니다.
정상: 답변이 “현재 1개”를 말하고, 근거가 붙습니다.
멈춤: 답변이 3개라고 하면 실제 Pod 상태와 챗봇이 읽는 namespace/selector가 어긋난 것입니다.

질문 2: 해결 계획 만들기

이제 “부족하면 3개로 올려 달라”고 말합니다. 이때 중요한 점은 바로 실행하지 말고 승인 버튼을 기다리게 하는 것입니다.

챗봇 입력창에 그대로 붙여넣기
komsco-ai-dev 네임스페이스의 aiops-two-pod-exec 파드가 3개여야 하는데 현재 부족하면 3개로 올리는 해결 계획을 만들어줘. 실행은 바로 하지 말고 승인 버튼을 기다려.

답변에서 봐야 할 것

  • 문제: 현재 replica 또는 Pod 수가 정상 기준보다 부족하다고 설명합니다.
  • 해결: replicas를 3으로 맞추는 계획을 제시합니다.
  • 흐름: ActionProposal -> SealedActionPlan -> ApprovalDecision -> ExecutionRecord가 보입니다.
  • 답변 안에 승인과 거절 버튼이 보입니다.
멈춤: 답변은 있는데 버튼이 없으면, 화면이 read-only 모드이거나 Action Executor가 꺼져 있을 수 있습니다. 상단 실행 모드를 실행 가능으로 바꾸고 다시 질문하세요.

버튼 클릭

1

승인 버튼 클릭

챗봇 답변 안에 있는 승인 버튼을 누릅니다.

정상: 잠시 뒤 승인 완료 메시지 또는 Approval 기록이 보이고, 다음 단계로 실행 버튼이 나타납니다.
멈춤: 버튼이 비활성화면 hover/title에 나오는 이유를 읽고 기록하세요.
2

실행 버튼 클릭

승인이 끝난 뒤 새로 나타나는 실행 버튼을 누릅니다.

정상: 실행 완료 메시지, ExecutionRecord, 또는 verified 계열 결과가 보입니다. 내부적으로는 set_replicas_within_bounds 조치가 실행됩니다.
멈춤: 실행 실패 메시지가 나오면 내용을 그대로 복사합니다. 특히 권한, planDigest, stale evidence, Action Executor 연결 오류를 확인합니다.

oc -n komsco-ai-dev get deployment aiops-two-pod-exec

챗봇에게 다시 확인시키기

komsco-ai-dev 네임스페이스의 aiops-two-pod-exec 파드가 이제 3개로 복구됐는지 다시 확인해줘.
정상: 챗봇이 현재 3개라고 말하고, 근거 footer 또는 RCA Context에 수집 근거가 붙습니다.

남길 증거

해결 전 터미널

oc get deployment 결과가 1개 상태를 보여야 합니다.

해결 전 콘솔

Deployment 또는 Pod 화면에서 Pod 1개가 보여야 합니다.

챗봇 답변

문제 설명, 해결 계획, 승인/거절 버튼, 실행 버튼이 보여야 합니다.

해결 후 터미널/콘솔

Deployment 3개, Pod 3개 Running/Ready가 보여야 합니다.

체크내가 확인한 것
대상 Deployment가 존재했다.
해결 전 Pod 1개를 봤다.
챗봇이 현재 1개라고 답했다.
챗봇 답변 안에 승인/거절 버튼이 떴다.
승인 후 실행 버튼이 떴다.
실행 후 Pod 3개를 봤다.
마지막 질문에서 챗봇이 3개 복구를 근거와 함께 확인했다.

막히면 여기부터 본다

증상원인 계층확인할 것다음 행동
대상 Deployment가 없다 테스트 데이터 없음 oc -n komsco-ai-dev get deployment aiops-two-pod-exec 테스트 리소스 생성 절차가 필요합니다. scale 명령은 실행하지 않습니다.
챗봇이 현재 수를 틀리게 말한다 route/context mismatch namespace, selector, 질문 문구 질문에 namespace와 deployment 이름을 다시 넣습니다.
승인/실행 버튼이 안 뜬다 UI/action lifecycle 실행 모드, Action Executor configured, Mutations on 상단을 실행 가능으로 바꾸고 다시 질문합니다.
승인은 되는데 실행 실패 executor/permission/stale plan 오류 메시지, planDigest, 권한, Action Executor 연결 오류를 복사하고 task kugnus:actions:live-verify로 executor 경로를 점검합니다.
실행 후에도 1개다 mutation/postcondition oc get deployment, HPA, rollout status HPA 여부와 scale 권한을 확인하고 긴급 원복 명령을 실행합니다.
문제 진단용 명령
task kugnus:dev:doctor
task kugnus:actions:live-verify
task kugnus:aiops:verify

WSL 터미널에서 입력

oc -n komsco-ai-dev rollout status deployment/aiops-two-pod-exec --timeout=120s
oc -n komsco-ai-dev get deployment aiops-two-pod-exec
oc -n komsco-ai-dev get pods -l app=aiops-two-pod-exec
정상: Pod 3개가 다시 보이면 테스트 환경은 복구된 것입니다.

작성 기준: 현재 repo 코드와 Taskfile, Gateway action lifecycle 계약. 보호 문서인 docs/aiops-beginner-guide.html는 읽기 기준으로만 사용했고 수정하지 않았습니다.
