JSON Body 필드 설명

응답 흐름 읽는 법 — 터미널 출력 해석

Response Reading

응답은 data: {...} 형태의 JSON이 한 줄씩 흘러옵니다. 각 줄의 "type" 필드로 어떤 단계인지 알 수 있습니다.

SSE Stream예상 응답 흐름 (순서대로)
# ① 시연 증적 수집 시작 알림
data: {"type": "tool_call", "name": "past_pod_restart_demo_evidence",
       "summary": "과거 Pod 재시작 RCA 시연 증적 수집 (Scenario 11)"}

# ② Event 증적 수집 완료
data: {"type": "tool_result", "name": "openshift_event_lookup",
       "status": "success", "evidenceType": "event",
       "detail": "...OOMKilled · Container exceeded memory limit of 512Mi"}

# ③ Pod Snapshot 수집 완료
data: {"type": "tool_result", "name": "openshift_pod_snapshot_lookup",
       "status": "success", "evidenceType": "snapshot",
       "detail": "...restartCount=3, lastState.terminated.reason=OOMKilled"}

# ④ Pod 상태 수집 완료
data: {"type": "tool_result", "name": "openshift_pod_status_lookup",
       "status": "success", "evidenceType": "pod_status"}

# ⑤ 로그 패턴 수집 완료
data: {"type": "tool_result", "name": "openshift_pod_log_pattern_probe",
       "status": "success", "evidenceType": "pod_log",
       "detail": "...java.lang.OutOfMemoryError: Java heap space"}

# ⑥ 런북 검색 완료
data: {"type": "tool_result", "name": "gateway_rag_runbook_search",
       "status": "success", "evidenceType": "runbook"}

# ⑦ Metric — missing (정상, v0.1.9 예정)
data: {"type": "tool_result", "name": "openshift_metric_query",
       "status": "skipped", "evidenceType": "metric"}

# ⑧ ClusterOperator — missing (정상)
data: {"type": "tool_result", "name": "openshift_clusteroperator_lookup",
       "status": "skipped", "evidenceType": "clusteroperator"}

# ⑨ OLS 최종 답변 스트리밍 시작
data: {"type": "token", "content": "### 확인된 근거\n\n..."}
data: {"type": "token", "content": "..."}
...

# ⑩ 스트리밍 종료
data: {"type": "done"}
👀 "status": "skipped"로 나오는 metric·clusteroperator는 오류가 아닙니다. "현재 수집하지 않았고 missing evidence로 처리한다"는 정상 동작입니다. OLS 최종 답변에서 "추가 확인 필요" 섹션에 표시됩니다.
5

예상 최종 답변 형태

Expected Answer

OLS가 생성하는 최종 답변은 아래 5개 섹션을 포함합니다. 답변 계약에 의해 이 순서가 강제됩니다.

### 확인된 근거

  • event — 2026-06-28 02:14 KST, OOMKilled, Container exceeded memory limit 512Mi (collected)
  • snapshot — restartCount=3, lastState.terminated.reason=OOMKilled (collected)
  • pod_status — webapp-deploy-7f94d-k8z2p RESTARTS=3, STATUS=Running (collected)
  • pod_log — java.lang.OutOfMemoryError: Java heap space, GC overhead limit exceeded (collected)
  • runbook — OOMKilled 대응 런북 검색 완료 (collected)

### 가능한 원인 후보

  • Java 애플리케이션의 heap 메모리 설정이 Pod memoryLimit(512Mi)에 비해 과도하게 설정됨
  • 메모리 누수(Memory Leak)로 인한 점진적 heap 증가
  • ※ Prometheus 장기 메트릭(memory 추이)이 missing이므로 원인을 확정하지 않습니다

### 추가 확인 필요

  • metric (missing) — Prometheus 메모리 장기 추이 (v0.1.9 예정)
  • clusteroperator (missing) — 클러스터 레벨 이상 여부

### Read-only 확인 순서

  • oc describe pod webapp-deploy-7f94d-k8z2p -n default
  • oc get events -n default --sort-by=.lastTimestamp
  • 메모리 limit 증설은 MP-CHG 또는 변경 관리 절차에 따라 승인 후 진행

### 금지 작업

  • oc delete pod / rollout restart / scale — 이 답변에서 직접 실행 금지
  • 원인 확정 금지 — metric missing 상태에서 "메모리 누수가 원인"이라고 단정하지 않음
📌 실제 OLS 답변은 위보다 자세하고 자연스러운 한국어로 나옵니다. 위는 답변 구조를 예시한 것입니다. 핵심은 5섹션 구조가 반드시 포함된다는 점입니다.

응답 더 예쁘게 보기 (선택)

Formatting Tips

SSE 스트림을 그대로 보면 JSON이 한 줄씩 흘러서 읽기 어렵습니다. 아래 방법으로 더 보기 좋게 출력할 수 있습니다.

방법 A — tool_result만 골라서 보기
bashgrep 필터
curl -s -N \
  -X POST $GW/v1/chat/stream \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "message": "어제 새벽에 default namespace Pod가 왜 재시작됐어?",
    "pageContext": {
      "namespace": "default",
      "aiopsDemoCycle": {"scenarioId": "past-pod-restart-rca"}
    }
  }' | grep "tool_result\|tool_call\|done"
방법 B — token 타입만 이어붙여서 최종 답변 텍스트 확인
bash + python3최종 답변만 추출
curl -s -N \
  -X POST $GW/v1/chat/stream \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "message": "어제 새벽에 default namespace Pod가 왜 재시작됐어?",
    "pageContext": {
      "namespace": "default",
      "aiopsDemoCycle": {"scenarioId": "past-pod-restart-rca"}
    }
  }' | python3 -c "
import sys, json
for line in sys.stdin:
    line = line.strip()
    if not line.startswith('data: '): continue
    try:
        d = json.loads(line[6:])
        if d.get('type') == 'token':
            print(d.get('content',''), end='', flush=True)
    except: pass
print()

Troubleshooting
증상 원인 해결
Connection refused / 응답 없음 Gateway가 실행 중이지 않음 task kugnus:gateway:start
또는 uvicorn 직접 실행
401 Unauthorized Bearer 토큰 없거나 만료됨 oc whoami -t 로 토큰 재발급
TOKEN 변수 재설정
시연 증적이 안 나오고 실제 OCP 호출 시도 pageContext에 aiopsDemoCycle 필드 누락 JSON Body에 "aiopsDemoCycle": {"scenarioId": "past-pod-restart-rca"} 추가 확인
tool_result는 나오는데 최종 답변(token)이 안 나옴 OLS(Lightspeed) 연결 없음 OLS 없는 환경에서는 Gateway fallback 답변이 나오거나 응답이 짧을 수 있음 — 정상
metric status가 "success"로 나옴 PROMETHEUS_URL 환경 변수가 설정되어 있고 실제 Thanos가 연결된 경우 정상 동작. 시연에서는 skipped가 기대값이지만 실제 연결 시 success도 가능
응답이 너무 빨리 끊김 curl -N 플래그 누락 curl 명령에 -N 반드시 포함

전체 체크리스트 한눈에 보기

Checklist
  • Gateway 실행 확인
    curl -s http://localhost:8000/health → {"status":"ok"}
  • TOKEN 변수 설정
    TOKEN=$(oc whoami -t) 또는 Bearer 토큰 직접 지정
  • 시연 요청 전송
    curl -s -N -X POST $GW/v1/chat/stream -H "Authorization: Bearer $TOKEN" + JSON Body에 aiopsDemoCycle.scenarioId = "past-pod-restart-rca" 포함
  • 증적 수집 이벤트 확인
    event ✓ snapshot ✓ pod_status ✓ pod_log ✓ runbook ✓ metric missing clusteroperator missing 이 순서로 나오는지 확인
  • 최종 답변 5섹션 확인
    확인된 근거 / 가능한 원인 후보 / 추가 확인 필요 / Read-only 확인 순서 / 금지 작업 이 5개 헤더가 답변에 포함되는지 확인
🎉 5단계가 모두 확인되면 Scenario 11 시연 완료입니다. 총 소요 시간 약 2~3분. OCP 클러스터 없이도 완전한 RCA 흐름 시연이 가능합니다.
