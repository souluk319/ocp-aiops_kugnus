Local Operations Runbook

localhost:9000을 매번 삽질 없이 켜는 법

이 문서는 OKD 로컬 콘솔에서 AIOps for OCP를 테스트할 때 필요한 Gateway, 플러그인 dev-server, OKD console bridge의 역할과 기동 순서를 고정한다. 목표는 “화면이 떴다”가 아니라 “Copilot이 실제로 질문을 받고 Gateway까지 연결된다”를 확인하는 것이다.

9000 · OKD Console 브라우저가 여는 로컬 OKD 콘솔. Docker 컨테이너가 회사 OKD API를 대신 조회한다.
9001 · Plugin AIOps 화면과 Copilot UI 번들을 제공한다. chunk 하나라도 404면 화면이 blank가 된다.
18080 · Gateway Copilot 질문을 받아 OCP 조회, Lightspeed, Action Plan 흐름으로 연결한다.
18443 · Lightspeed PF OpenShift Lightspeed 서비스 port-forward. 연결 실패 시 Gateway fallback/실조회로 구분된다.

대부분의 경우 아래 한 줄만 실행한다. 긴 strict demo gate는 생략하고, 로컬 작업에 필요한 stack만 올린다.

WSL · repo root
cd /home/kugnus/cywell/ocp-aiops_kugnus
task kugnus:aiops:up

상태만 보고 싶으면 수리 없이 doctor를 실행한다.

진단만
cd /home/kugnus/cywell/ocp-aiops_kugnus
task kugnus:aiops:doctor

VPN이나 oc 토큰을 다시 잡은 뒤 콘솔 bridge만 새로 만들고 싶으면 repair를 실행한다.

수리
cd /home/kugnus/cywell/ocp-aiops_kugnus
task kugnus:aiops:repair
성공 기준: 마지막에 9001 plugin assets, 9000 Kubernetes API, 9000 Gateway proxy가 모두 통과해야 한다. 브라우저 주소는 http://localhost:9000/dashboards/aiops 이다.
주의: cd komsco-ai-console-plugin && corepack yarn build를 실행하면 production dist가 써지면서 dev용 plugin-entry.js와 일부 고정 chunk가 사라질 수 있다. build 후 브라우저 테스트를 계속하려면 task kugnus:aiops:repair로 9001 dev-server를 다시 맞춘다.

원리

문제는 localhost 하나가 아니라 네 개의 로컬 경로가 함께 맞아야 한다는 점이다.

브라우저
사용자는 localhost:9000만 본다.
OKD bridge
Docker 컨테이너 kugnus-local-console이 현재 oc 토큰으로 회사 OKD API를 조회한다.
Plugin dev-server
9001이 AIOps 화면 chunk를 제공한다. manifest만 200이어도 필수 chunk가 404면 화면이 runtime overlay로 죽는다.
Gateway
18080이 Copilot API다. WSL Docker 컨테이너에서는 localhost:18080이 아니라 host.docker.internal:18080로 봐야 한다.

수동 기동

원리를 확인하고 싶을 때만 아래 순서로 나눠 켠다. 평소에는 task kugnus:aiops:up을 쓴다.

1. oc 로그인 확인

회사 OKD API 확인
oc whoami
oc whoami --show-server

서버는 https://api.ocp.cywell.server:6443이어야 한다. VPN이 끊긴 상태면 여기서 먼저 실패한다.

2. Gateway 켜기

Gateway + Lightspeed path
cd /home/kugnus/cywell/ocp-aiops_kugnus
GATEWAY_HOST=0.0.0.0 \
AIOPS_GATEWAY_MODE=execute \
OLS_BASE_URL=https://127.0.0.1:18443 \
./scripts/dev-gateway-lightspeed.sh

3. Plugin dev-server 켜기

9001 plugin
cd /home/kugnus/cywell/ocp-aiops_kugnus/komsco-ai-console-plugin
PATH="$HOME/.nvm/versions/node/v24.14.0/bin:$PATH" \
corepack yarn webpack serve --progress

4. OKD console bridge 켜기

9000 console bridge
cd /home/kugnus/cywell/ocp-aiops_kugnus
OPEN_BROWSER=false ./scripts/open-okd-console.sh
WSL + Docker에서는 console bridge가 Gateway를 host.docker.internal:18080로 봐야 한다. 이번 수정으로 .env에 GATEWAY_ENDPOINT=http://localhost:18080이 있어도 WSL에서는 자동 보정된다.

정상 판정

아래가 모두 HTTP 200이면 브라우저 테스트를 시작해도 된다.

필수 health gate
curl -ksS http://127.0.0.1:18080/healthz
curl -sS -I http://127.0.0.1:9001/api/plugins/cywell-aiops-console-plugin/plugin-manifest.json
curl -sS -I http://127.0.0.1:9001/api/plugins/cywell-aiops-console-plugin/exposed-NullContextProvider-chunk.js
curl -ksS http://127.0.0.1:9000/api/kubernetes/version
curl -ksS http://127.0.0.1:9000/api/proxy/plugin/cywell-aiops-console-plugin/ai-gateway/healthz
게이트 의미 실패하면
18080/healthz Gateway가 살아 있다. Gateway 프로세스나 Lightspeed port-forward 로그를 본다.
9001/plugin-manifest.json 플러그인 dev-server가 응답한다. Node 24 경로와 webpack 로그를 본다.
9001/exposed-NullContextProvider-chunk.js 콘솔 overlay hook에 필요한 chunk가 실제로 있다. manifest만 정상인 stale 9001 상태다. task kugnus:aiops:repair를 실행한다.
9000/api/kubernetes/version local console bridge가 OKD API를 조회한다. VPN, oc token, bridge 컨테이너 토큰을 확인한다.
9000/.../ai-gateway/healthz 브라우저에서 Copilot이 Gateway까지 닿는다. bridge proxy endpoint가 host.docker.internal:18080인지 본다.

장애별 조치

증상 대부분의 원인 바로 할 일
브라우저가 blank이고 빨간 runtime overlay 9001 plugin chunk 404 또는 stale HMR 산출물 task kugnus:aiops:repair, 그래도 안 되면 9001 webpack 로그 확인
Copilot에 BadGateway Gateway가 꺼졌거나 bridge가 localhost:18080로 잘못 연결 curl 18080/healthz와 9000 ... ai-gateway/healthz 둘 다 확인
Node/Operator 빨간불 실제 클러스터 문제이거나 Gateway summary 조회 실패 oc get nodes, oc get co, Gateway health를 분리 확인
9000은 뜨는데 데이터가 낡음 Docker bridge가 오래된 oc 토큰을 들고 있음 VPN/oc 재로그인 후 task kugnus:aiops:repair
영어 UI인데 한글 답변 요청 payload에 UI language가 전달되지 않거나 Gateway 답변 계약이 한국어로 고정 Copilot stream payload의 language와 Gateway answer language contract 확인

이번에 고친 점

  • open-okd-console.sh가 manifest뿐 아니라 필수 plugin chunk까지 확인한다.
  • WSL에서 GATEWAY_ENDPOINT=http://localhost:18080가 들어와도 console bridge에는 host.docker.internal:18080로 보정한다.
  • kugnus-okd-console-morning.sh와 kugnus-demo-resume.sh의 plugin 정상 기준을 chunk 단위로 올렸다.
  • Taskfile.yml에 kugnus:aiops:up, kugnus:aiops:doctor, kugnus:aiops:repair 별칭을 추가했다.
