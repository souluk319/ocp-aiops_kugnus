# KOMSCO AIOps 독립모드 UI 리디자인 플랜 (Ver.0.2.8.1)

본 플랜은 `http://localhost:5174/dashboards/`에서 제공되는 AIOps for OCP 독립모드의 전반적인 UI/UX를 한층 세련된 디자인, 고도화된 시각화, 그리고 시원한 가독성으로 개편하기 위한 계획서입니다. 

특히 `DESIGN.md`의 핵심 철학(마케팅 사이트가 아닌, **운영자가 압박 상황에서도 빠르게 판단하고 승인할 수 있는 조용하고 밀도 있는 Admin Console**)을 완벽히 준수하면서도 프리미엄 운영 도구로서의 시각적 퀄리티를 달성하는 데 목적이 있습니다.

---

## 1. 리디자인 핵심 원칙 (Core Principles)

1. **조용하고 밀도 있는 전문성 (Quiet & Dense)**: 불필요한 그라데이션, 화려한 장식을 배제하고 정보의 명도 대비를 통해 우선순위를 명확히 합니다.
2. **시원한 가독성과 타이포그래피**: 12px 이하의 본문 사용을 지양하고, 시스템 폰트 및 모노스페이스(Technical ID용)를 적절히 혼용하여 데이터 판독 속도를 높입니다.
3. **목적 지향적 레이아웃**: 상태 요약 $\rightarrow$ 우선 확인 $\rightarrow$ 근거 $\rightarrow$ Action Plan $\rightarrow$ 상세/감사 순으로 시선이 자연스럽게 이동하도록 구성합니다.
4. **고도화된 상태 및 데이터 시각화**: 차트나 뱃지는 화려함보다 정확성과 상태(정상/경고/위험)를 즉각 인지할 수 있도록 재설계합니다.

---

## 2. 전체 레이아웃 및 네비게이션 개선

### 2.1 좌측 네비게이션 패널 (Global Navigation)
- **그룹 분리 시각화**: `MONITORING`과 `OPERATIONS` 그룹 간의 여백과 라벨(navGroupLabel) 가독성을 개선하여 영역 구분을 명확히 합니다.
- **아이콘 및 타이포그래피 정제**: Lucide React 아이콘의 Stroke 두께와 텍스트 크기를 조정하여, 전체화면(Full Screen)에서 좌측 영역이 답답해 보이지 않고 시원하게 뚫린 느낌을 주도록 합니다.
- **상태 연동 뱃지**: 메뉴 옆에 크리티컬 알림(예: `알림 & 이벤트`, `RCA 센터`) 발생 시 작지만 가시성 높은 상태 뱃지를 추가하여 네비게이션 단계에서부터 이슈를 인지할 수 있게 합니다.

### 2.2 메인 뷰포트 공간 활용
- **카드 속 카드(Nested Cards) 제거**: UI 복잡도를 높이는 이중 카드 레이아웃을 평면적이고 분할된 그리드(Split Pane) 형태로 변경하여 정보의 중복 노출을 없앱니다.
- **오버레이/패널 연동**: 챗봇이나 상세 정보를 열었을 때, 메인 뷰를 밀어내거나(Squish) 오버레이가 남겨지는 현상을 방지하고, 닫을 때 연관 패널이 함께 깔끔하게 정리되도록 상태 관리를 최적화합니다.

## 3. 주요 메뉴별 기능 시각화 개선 (Menu-Specific Redesign)

### [MONITORING 그룹]

#### 1) 대시보드 (Dashboard)
- **개선 목표**: 현재 시스템 상태와 가장 시급한 Action Plan 후보를 한눈에 파악.
- **시각화 계획**: 
  - 상단: 클러스터 요약 지표 (CPU, Memory, Alerts) - 불필요한 원형 카드 대신 심플한 Metric Widget 사용.
  - 메인: **현재 발생한 이상 징후 리스트**와 **승인 대기 중인 Action Plan 후보**를 밀도 있는 테이블(또는 Compact Card) 형태로 배치.

#### 2) 실행 기록 (Executions)
- **개선 목표**: 복잡한 실행 로그를 직관적인 타임라인 및 감사 로그로 변환.
- **시각화 계획**: 실행 성공/실패/진행중 상태를 색상이 아닌 아이콘과 명확한 텍스트 배지로 구분. 로그 페이로드(JSON)는 기본적으로 숨기고 '상세 보기' 패널(Drawer)을 통해서만 노출.

#### 3) RCA 센터 (RCA Center)
- **개선 목표**: 근거 수집 상황과 원인 분석 트리를 명확히 표현.
- **시각화 계획**: 
  - 텍스트 중심의 나열을 탈피하여, 문제 발생 $\rightarrow$ 수집된 근거(Evidence) $\rightarrow$ 분석 도구(Tool) $\rightarrow$ 결론(RCA)으로 이어지는 노드 기반 시각화 또는 스텝퍼(Stepper) 형태 도입.
  - 내부 용어(`RCA 문맥 연결` 등) 배제, 운영자 친화적 언어(`근거 수집 중`, `답변 생성 중`) 적용.

#### 4) 서비스 맵 (Service Map)
- **개선 목표**: 복잡한 네트워크 및 토폴로지를 시원하고 가볍게 시각화.
- **시각화 계획**: 노드 간의 연결 선을 얇고 명료하게 처리하며, 에러가 발생한 노드(Pod/Service) 주변에 뚜렷한 하이라이트(Glow가 아닌 Solid Border) 적용.

#### 5) 클러스터 리소스 (Endpoints) & 알림 (Alerts)
- **개선 목표**: 방대한 데이터를 압박감 없이 탐색할 수 있는 필터링 중심의 뷰.
- **시각화 계획**: Dense Table Layout 적용, 13~14px 기준의 편안한 행간, 긴 Technical ID는 말줄임표와 복사 기능이 결합된 Monospace Chip으로 표현.

### [OPERATIONS 그룹]

#### 6) 보고서 (Reports) & 위키 문서 (Wiki)
- **개선 목표**: 읽기 쉬운 본문 렌더링.
- **시각화 계획**: 문서 읽기에 최적화된 중앙 정렬 레이아웃(Max-width 800~1000px), 충분한 여백, 헤딩(H1~H3) 간의 명확한 크기 대비를 주어 가독성을 한층 끌어올림.

#### 7) 설정 (Settings)
- **개선 목표**: 권한, 실행 모드 등의 설정을 실수 없이 변경 가능하도록 구성.
- **시각화 계획**: `읽기 전용`, `실행 가능`, `실행 무제한`과 같은 실행 모드 토글을 큼직하고 클릭 영역이 확실한 Segmented Control 형태로 디자인.

---

## 4. AIOps 핵심 컴포넌트: Action Plan 상세 패널

AIOps의 가장 중요한 경험인 **승인(Approve) / 거절(Reject)** 경험을 극대화합니다.

- **레이아웃**: 좌/우 분할 레이아웃으로, 좌측에는 문제 상황과 근거(Evidence)를, 우측에는 Action Plan(대상, 조치, 예상 영향, 롤백 계획)과 승인 버튼을 배치.
- **버튼 디자인**: 화려함보다는 무게감 있는 Solid Button을 사용하고, 실행 취소나 거절 사유 입력 창은 직관적으로 나타나도록 모달(Modal) 또는 인라인 폼 적용.
