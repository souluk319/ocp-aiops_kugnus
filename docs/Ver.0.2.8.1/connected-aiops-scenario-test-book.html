Connected OKD Safe Scenario Course

실제 OKD 연결 상태에서 AIOps Copilot의 조회, 판단, 승인, 실행, 검증 흐름을 안전하게 시연합니다.

이 테스트북은 로컬 fixture가 아니라 회사 OKD에 연결된 상태를 전제로 합니다. 모든 변경은 매번 새로 만드는 aiops-copilot-e2e-* namespace 안에서만 수행하고, cleanup은 안전 label이 모두 맞을 때만 동작합니다.

Connected 시나리오

00

Sandbox namespace 생성

timestamp 기반 격리 namespace, quota, limitrange, 테스트 workload를 만듭니다.

PENDING

실행 명령

bash scripts/setup-v0281-connected-aiops-sandbox.sh

직접 볼 것

  • oc whoami --show-server가 승인된 회사 OKD server와 일치한다.
  • namespace 이름이 aiops-copilot-e2e-*이고 safety label 4개가 붙었다.
  • 정상, scale 대상, CrashLoopBackOff, ImagePullBackOff workload가 분리되어 있다.
01

Preflight

OKD 콘솔, plugin entry, gateway health, namespace 권한을 확인합니다.

PENDING

검증 기준

  • http://localhost:9000/api/kubernetes/version이 200이다.
  • plugin entry와 gateway health가 200이다.
  • test namespace 안에서 get/patch deployment 권한이 있다.
02

AIOps Copilot 열기

OKD 콘솔 우측 하단 토글에서 Copilot을 열고 연결 상태를 확인합니다.

PENDING

직접 볼 것

  • 챗봇 헤더 명칭이 AIOps Copilot으로 보인다.
  • Gateway/Lightspeed 상태가 숨겨지지 않고 작은 상태 라벨로 보인다.
  • 실행 모드 3개가 버튼 오버플로 없이 보인다.
03

Read-only 장애 진단

조회 근거와 read-only 명령만 제공하고 실행 버튼은 없어야 합니다.

PENDING

입력 질문

aiops-copilot-e2e-* namespace에서 CrashLoopBackOff와 ImagePullBackOff 상태를 실제 근거 중심으로 조회해줘. 변경은 하지 말고 read-only oc 확인 명령도 같이 정리해줘.

직접 볼 것

  • 답변에 test namespace가 명시된다.
  • oc get, oc describe, oc logs 같은 조회 명령만 나온다.
  • 승인/실행 버튼이 없다.
04

실행 가능 모드 Action Plan

승인 전에는 mutation 없이 계획만 생성되어야 합니다.

PENDING

입력 질문

Deployment aiops-copilot-e2e-*/aiops-connected-scale-target 를 2개로 scale하는 실행 계획을 생성해줘. 승인 전에는 실행하지 말고, 영향/검증/롤백 조건을 포함해줘.

직접 볼 것

  • Action Plan 또는 승인 필요 상태가 보인다.
  • 승인 전 spec.replicas가 1로 유지된다.
  • 대상은 test namespace의 scale target으로 제한된다.
05

승인 게이트

승인 버튼이 눌린 뒤에만 실행 버튼 또는 실행 가능 상태로 넘어갑니다.

PENDING

직접 볼 것

  • 승인 전 실행 기록이 생기지 않는다.
  • 승인 후 승인 기록 또는 실행 버튼이 보인다.
  • 서버 정책상 승인 차단이면 reason이 report에 남는다.
06

승인된 실행

실행 후 변경은 test deployment scale 1→2로만 제한됩니다.

PENDING

직접 볼 것

  • aiops-connected-scale-target만 replicas 2가 된다.
  • ExecutionRecord 또는 실행 완료 문구가 보인다.
  • 다른 namespace 리소스는 변경하지 않는다.
07

검증

rollout status와 ready 상태로 실행 결과를 확인합니다.

PENDING

검증 명령

oc get deploy aiops-connected-scale-target -n aiops-copilot-e2e-*
oc rollout status deployment/aiops-connected-scale-target -n aiops-copilot-e2e-*

직접 볼 것

  • replicas가 2로 바뀐다.
  • ready 상태가 report에 남는다.
08

Cleanup

safe label과 session label이 모두 맞는 namespace만 삭제합니다.

PENDING

실행 명령

bash scripts/cleanup-v0281-connected-aiops-sandbox.sh --namespace aiops-copilot-e2e-YYYYMMDDHHMMSS --session YYYYMMDDHHMMSS

직접 볼 것

  • safe-delete, suite, session label이 모두 맞아야 삭제된다.
  • 삭제 후 oc get ns가 not found가 된다.
보호 기준: 이 테스트북은 기존 로컬 runner와 Claude scenario JSON을 수정하지 않습니다. 실제 연결 테스트는 새 namespace 안에서만 수행하고, 결과는 report JSON과 screenshot으로 남깁니다.
