제로베이스 설치와 재부팅 복구 실행 안내서

이 문서는 사용자가 직접 터미널에 입력해서 로컬 개발 콘솔을 복구하고, RAG/챗봇/대시보드 검증까지 갈 수 있게 만든 실행 안내서다. 기준 작업대는 Windows 탐색기 경로가 아니라 WSL 네이티브 경로 /home/kugnus/cywell/ocp-aiops_kugnus다.

목적

목표재부팅, Docker 재시작, VPN 끊김 이후에도 사용자가 스스로 로컬 시연 환경을 다시 띄운다.
완료 조건http://localhost:9000/dashboards에서 Cywell AI 챗봇이 열리고, PDF 업로드 RAG와 RCA 응답 검증이 PASS다.
검증 방법task kugnus:dev:doctor, task kugnus:runtime:smoke, task kugnus:rag:file-upload:smoke, task kugnus:rag:chat:smoke, task kugnus:ui:verify.
하지 않을 것회사 OCP/OKD 클러스터에 카탈로그 설치, OLM 설치, 런타임 배포를 임의 실행하지 않는다.

전체 그림

WSL Ubuntu 코드, Node/Yarn, Python, Task, Gateway, verifier가 돌아가는 실제 작업대다.
Docker Desktop 로컬 OpenShift console bridge와 pgvector RAG DB가 기대는 컨테이너 실행 기반이다. Windows 앱이지만 WSL integration이 켜져 있어야 한다.
회사 OCP 연결 oc login으로 회사 OCP의 현재 상태와 Lightspeed/ActionExecutor 서비스를 읽고 port-forward한다. 설치 대상이라는 뜻은 아니다.
로컬 콘솔 브라우저의 http://localhost:9000/dashboards에서 OpenShift 콘솔과 Cywell AI plugin을 확인한다.
한 줄로 말하면, 회사의 실제 OCP 상태를 읽어 와서 WSL 로컬 콘솔에서 제품을 개발하고 검증하는 구조다.

제로베이스 준비

아예 새 PC 또는 새 WSL에서 출발한다면 아래 순서로 생각한다. 이미 설치된 것은 재설치하지 않고 version 확인만 해도 된다.

1. 필수 도구 확인

python3 --version
node --version
corepack --version
task --version
oc version --client
docker version
rg --version
PythonGateway와 verifier 실행.
Node/Corepack/Yarnconsole plugin build와 webpack dev server 실행.
Go Taskrepo의 표준 실행 명령 묶음. Ubuntu의 taskwarrior와 다르다.
oc회사 OCP 상태 조회와 port-forward.
Docker로컬 console bridge와 pgvector DB 실행.
ripgrep rg코드와 문서 빠른 검색.

2. 부족한 apt 도구 설치

sudo apt-get update
sudo apt-get install -y python3-pip ripgrep gh

Node는 현재 이 repo에서 NVM 기반 /home/kugnus/.nvm/versions/node/v24.14.0/bin/node를 정상 기준으로 본다.

3. Docker Desktop 확인

Windows Docker Desktop에서 Settings > Resources > WSL integration의 Ubuntu 토글이 켜져 있어야 한다.

docker version
정상 기준: Client와 Server 정보가 모두 보인다. Cannot connect to the Docker daemon이면 Docker Desktop 또는 WSL integration 문제다.

4. OpenShift 로그인

토큰은 웹 콘솔에서 받아서 직접 입력한다. 토큰은 문서나 git에 남기지 않는다.

oc login --token=붙여넣은_TOKEN --server=https://api.ocp.cywell.server:6443
oc whoami
oc whoami --show-server
정상 기준: 사용자명이 나오고 서버가 https://api.ocp.cywell.server:6443다.

5. RAG pgvector 준비

처음 한 번 또는 Docker 컨테이너가 사라졌을 때 실행한다. 이 명령은 장시간 붙잡고 있지 않고, 컨테이너 준비 후 종료된다.

task kugnus:rag:dev:up

발표용 설명

“이 프로젝트는 회사 OCP에 바로 설치한 것이 아니라, WSL 로컬에서 OpenShift console dynamic plugin과 Gateway를 띄워 회사 OCP/Lightspeed/ActionExecutor/RAG를 연결 검증하는 구조입니다.”
  • Frontend는 OpenShift Console dynamic plugin으로 올라가며 로컬 console bridge localhost:9000에서 확인한다.
  • Gateway는 localhost:18080에서 OCP 상태, Lightspeed, ActionExecutor, RAG 저장소를 하나의 AIOps API처럼 정리한다.
  • RAG는 PBS 업로드 파이프라인의 핵심 아이디어를 가져오되, 현재 제품에는 PDF/Office parser 경계와 pgvector 저장/검색 계약만 선별 이식했다.
  • Docs 화면은 원문 전체 노출 뷰어가 아니라, 적재 문서와 redacted chunk preview를 통해 “RAG에 들어갔는지”를 확인하는 운영 화면이다.
  • 현재 시연 범위는 로컬 개발 콘솔에서의 관측, RAG 업로드, RCA 응답, UI 검증이다.

하지 않을 것

아래 명령은 별도 승인 전까지 실행하지 않는다. 현재 기본 시연은 로컬 개발 콘솔 기준이다. 
task catalog:deploy
task catalog:release
task catalog:runtime:apply
task olm:deploy
task olm:release
task olm:install
task kugnus:install

또한 .env, token, kubeconfig, password, 인증정보는 읽거나 커밋하지 않는다.
