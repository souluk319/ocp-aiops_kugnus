Ver.0.1.5 Docs/RAG Management Brief

Branch: feat/v.0.1.5 · Scope: local console plugin UI and Gateway RAG API integration · No OCP/OKD install

현재 판단

PBS의 업로드 문서 뷰어 아이디어는 제품 관점에서 맞다. 다만 챗봇 좌측 히스토리 패널 안에 전체 뷰어를 넣으면 대화 UI가 무거워지고, RAG 적재 상태를 설명하기도 어렵다. 따라서 업로드 문서는 OpenShift 콘솔 좌측 메뉴의 Cywell AI > Docs 정식 화면에서 관리한다.

이번 목표는 "예쁜 파일 뷰어"가 아니라 "업로드 문서가 실제로 RAG 검색 가능한 근거로 적재됐는지 확인 가능한 화면"이다.

PBS에서 가져온 것과 바꾼 것

구분 PBS 구조 우리 Ver.0.1.5 적용
문서 위치 업로드 문서 reader/popover 중심 Cywell AI > Docs 정식 메뉴 화면으로 분리
뷰어 /uploads/documents/{id}/index.html 같은 viewer artifact를 열람 현재는 raw 원문 뷰어가 아니라 Gateway가 반환한 redacted RAG chunk preview 표시
RAG 검증 업로드 문서를 보여주는 경험이 강함 선택 문서를 /v1/rag/search로 다시 조회해 검색 가능성을 확인
운영 안전 문서 열람 중심 raw content는 기본 숨김, preview는 redaction 후 표시
상태 설명 뷰어 성공 여부 중심 문서 수, chunk 수, 저장 크기, checksum, ACL, preview status를 함께 표시

구현 범위

  • 콘솔 좌측 메뉴에 Cywell AI > Docs 추가
  • 동적 플러그인 route /aiops-kugnus/docs 추가
  • 업로드 파일 선택, 목록 새로고침, 업로드 문서 목록 표시
  • 선택 문서의 metadata, chunk count, size, checksum, ACL 표시
  • 선택 문서를 RAG search로 재조회해 redacted chunk preview 표시

아직 하지 않은 것

  • PBS 수준의 HTML/PDF full viewer artifact 생성은 아직 하지 않았다.
  • 원문 전체 파일을 그대로 노출하지 않는다. 현재 화면은 redacted chunk preview만 보여준다.
  • OKD/OCP 설치나 catalog 등록은 하지 않았다.
  • 청킹 알고리즘 자체를 고도화하지는 않았다. 이번 단계는 관리 화면과 검색 검증 연결이다.

다음 개선 후보

  • viewer artifact contract 추가: viewerPath, pageCount, renderStatus
  • chunk strategy 개선: heading-aware chunk, table-preserving chunk, page number metadata
  • 업로드 후 재색인 버튼과 ingestion report 상세 화면
  • 문서별 검색 테스트 패널: query 입력 후 어떤 chunk가 근거로 잡히는지 확인
  • PDF 원문 뷰어와 redacted RAG chunk preview를 나란히 비교하는 split view
